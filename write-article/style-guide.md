# 公众号文章风格指南

## 一、整体调性

- **不要 AI 味**：不用"首先/其次/总结"、不用"让我们一起"、不用"值得注意的是"等套话
- **有深度思考**：不做简单的信息搬运，要有自己的判断和洞察
- **第一人称叙事**："我"的视角，有情绪旅程，不是旁观者
- **口语化但不随意**：像一个聪明的朋友在认真跟你聊天，不是在写论文

## 二、结构设计

### 标题（双平台差异）

每篇文章必须同时给出：**微信版 10 个标题** + **头条版 10 个标题**，共 20 个。

---

#### 微信公众号标题规范

**核心调性**：读者是主动订阅者，对账号有信任基础，标题像朋友发来的一条消息，而不是广告。**"值得读"优先于"我要点"。**

**最佳长度**：15-20 字（比通用建议更短，口语感更强）

**结尾用句号"。"**，不用感叹号，不用问号——这是这个账号风格的核心标志，让标题有对话感而非广告感。

---

**实测高效公式（基于真实数据，从高到低）：**

| 公式 | 核心机制 | 实测案例 & 数据 |
|-----|---------|--------------|
| **故意不说完型** | 说了个大概念，不透露答案，靠订阅信任驱动点击 | `最近最让我惊喜的一个 AI 工具。` → 1.0万读 |
| **热词锚定 + 新信息型** | 用当下最热的产品/公司名做锚，加一个读者关心的新信息 | `腾讯版的 OpenClaw 来了，关键是送免费 Token。` → 4.3万读 |
| **体验 + 情感化结论型** | 说我做了某事，结尾给出颠覆感/惊喜感的结论 | `在字节 Coze 里玩了 OpenClaw 和 Skill 后，我看到了新世界的大门。` → 3.0万读 |
| **大厂动态 + 实用亮点型** | 巨头入场消息 + 一个对读者有用的具体点 | `阿里下场做了类 OpenClaw 的产品，完美支持 Windows。` → 1.8万读 |
| **第一人称观点型** | "我"的判断，有立场感，但不要太具体（太具体反而没悬念） | `我觉得现在是选 AI 模型的最后窗口期。` |
| **反差/类比型** | 用已知事物类比，触发"原来如此"感 | `AI 的免费午餐，和当年网约车是一个结局。` |

---

**关键反例（数据证伪）：**
- `我用国产的 OpenClaw，搞定了小红书的运营。` → 仅 3138 读
- 原因：太具体，读者一眼看完，没有点进去的动机。**过于完整的标题反而杀死好奇心。**

---

**微信标题禁忌：**
- 不用感叹号、问号结尾（头条风，破坏对话感）
- 不用"震惊""万万没想到""千万"等低质词
- 避免超过 22 字
- 不要在标题里把文章内容说完——留一个"缺口"让人点进来
- 标题暗示的"发现/结论"，正文中必须有章节兑现

---

#### 今日头条标题规范

**核心调性**：碎片化、话题感、算法驱动；读者是被动推荐，标题须在 0.5 秒内抓住注意力。

**最佳长度**：25-30 字（算法偏好信息密度高的长标题）

**8 大公式：**（详见 write-article skill 中的完整公式说明）

数字型 / 反差对比型 / 悬念省略型 / 设问疑问型 / 利益实用型 / 第一人称故事型 / 焦虑痛点型 / 元素并列悬念型

---

**通用原则：**
- 好奇驱动 > 恐惧驱动
- 标题里的关键词/数字优先放句首
- 标题暗示的内容，正文必须兑现

### 开头（前3句话定生死）
- 用一个**具体故事/事件/细节**炸开场
- 不要从定义、背景、概括开始
- 3句话内必须制造悬念或震惊感

### 正文章节
- 每个章节有独立小标题，口语化、有张力
- 好的示例：「然后，字节自己踩了刹车」「这不是未来的事——它已经在发生」
- 差的示例：「Seedance 2.0 的技术特点」「深度伪造案例分析」

### 情绪曲线（必须有起伏）
```
震惊/好奇（开场钩子）
  → 惊叹（技术能力展示）
    → 紧迫感（时效性信息）
      → 恐惧/担忧（真实案例）
        → 反思（哲学升华）
          → 行动号召（结尾）
```

### 结尾
- 给读者一个**今天就能做的事**
- 制造转发动机：让读者觉得"我要让身边的人知道这件事"
- 最后一句话要有力，适合截图传播

## 三、写作技巧

### 节奏控制
- 长句和短句交替，不要连续3个以上长句
- 重要判断用**短句单独成段**
- 示例：「是警告。」「争议迅速发酵。」

### 引用与案例
- 案例要有**具体数字**（2亿港币、69万美元、500所学校）
- 引用真实人物的原话，标注来源
- 用案例卡片形式呈现（背景色块 + 加粗地点时间）

### 金句设计
- 每篇至少 2-3 个可截图传播的金句
- 放在引用块中突出显示
- 示例：「技术一夜之间就能迭代。而信任，需要几代人去重建。」

### 过渡
- 章节之间用装饰分割线（· · · 或 ◆ ◇ ◆）
- 段落之间自然过渡，不用"接下来我们讨论"

## 四、素材要求

### 调研
- 写文章前必须搜索最新信息和热门讨论
- 找到 2-4 个真实案例/数据支撑观点
- 引用行业关键人物的原话

### 事实核查（每次写作/修改必须执行，不可跳过）

**触发时机**：每次新增或修改涉及以下内容时，必须用 WebSearch 核实后才能写入文章：
- 具体数字（金额、比例、用户数、排名）
- 公司/产品动态（上线、发布、定价、融资）
- 引用的案例或事件
- 统计数据或行业报告结论

**核查标准**：
- 每个关键数字至少找到**原始来源**（官方公告/财报/新闻报道）
- 时间敏感数据需标注时间节点（如"2024年5月"）
- 模糊表述用"约/近/多款"兜底，不用精确数字掩盖不确定性
- 无法核实的内容，写"据报道"或删除，不得以猜测写成事实

**输出核查清单**：完成初稿后，列出文章中所有数字/案例/引语，逐条标注"✅ 已核实（来源）/ ⚠️ 待核实 / ❌ 已修正（原文→改后）"，告知用户。

### 配图
- 每篇 3-4 张配图
- 在 HTML 注释中标注推荐关键词和来源
- 封面图要在缩略图尺寸下仍有视觉冲击力

## 五、排版规范（公众号 HTML）

### 色彩体系
- 正文色：`#3a3a3a`
- 强调色/小标题：`#d4a574`（暖金色）
- 警示引用边框：`#c0392b`（红色）
- 金句引用背景：`#fdfbf8`
- 案例卡片背景：`#f7f7f7`
- 辅助文字：`#999` / `#bbb` / `#ccc`

### 字号体系
- 正文：`15px`
- 章节标题：`18px`，加粗，左侧 4px 色条
- 核心金句：`16px`，斜体或加粗
- 居中大字金句：`20-22px`，加粗
- 辅助标注：`12-13px`

### 间距与排版
- 行高：`2.0`（正文）
- 字间距：`1px`（正文）、`2px`（标题）
- 段间距：`margin: 15px 0`
- 引用块：左侧 3px 色条 + 内边距 `15px 20px` + 浅色背景
- 案例卡片：圆角 `8px` + 内边距 `18px 20px`

### 页面结构模板
```
封面引导语（居中，13px，灰色，类目标签）
标题（居中，22-24px，加粗）
分割线（◆ ◇ ◆）
封面大图
正文章节 × N（小标题 + 段落 + 引用块/案例卡片）
章节间分割线（· · ·）
结尾金句（引用块，加粗）
行动号召
END 标记
参考来源
```

## 六、输出格式

- 输出为 **HTML 文件**，使用内联样式（公众号不支持外部 CSS）
- `<body>` 外包一层预览样式：`max-width: 680px; margin: 0 auto;`
- 配图位置用 `<img src="请替换为配图URL">` 占位
- 每处配图用 HTML 注释标注建议关键词、风格、来源
